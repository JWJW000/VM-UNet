## 2. 本次代码准备

| 文件 | 用途 |
|---|---|
| `audit_training.py` | CPU 解析历史日志，导出验证曲线及大幅下降记录；不猜测原因 |
| `prepare_full_split.py` | 按文件 ID 配对图像/掩码，冻结划分，检查路径和 train/val 完全相同的图像文件 |
| `analyze_full.py` | 加载旧/新权重，导出逐图指标、面积分组和最差案例图 |
| `train_full.py` | 独立全监督入口；逐轮验证、CSV、按 pooled Dice 选模型、原子检查点、断点恢复 |
| `fullsup/` | 数据、损失和指标实现 |

不改动原版 `train.py` 与 SSL 训练行为。新入口不是原实验的逐位复现：数据处理、随机数顺序、选模规则及默认学习率周期有明确变化，必须先跑新入口 baseline，再比较方法。

### 新入口的固定设置

- 模型配置与当前 ISIC 基线一致：depths=[2,2,2,2]，decoder=[2,2,2,1]，drop_path=0.2，单类输出。
- 默认 BCE + per-image soft Dice；全部训练样本使用人工标注；没有教师、伪标签、扫描扰动。
- AdamW，lr=0.001，weight_decay=0.01，batch_size=32，300 epochs，256×256。
- 默认 cosine T_max=epochs，避免旧 T_max=50 在 300 轮中反复下降/上升；这是一项协议变化，**尚不能据此解释旧异常**。可用 `--t-max 50` 做专门对照。
- `--preprocessing corrected`：每次增强重新采样旋转角，掩码最近邻缩放；图像仍用与旧实现代数等价的逐图 min-max 到 [0,255]，对常量图防除零。
- `--preprocessing legacy`：保留初始化单角度旋转、掩码双线性缩放；仅用于受控诊断，不保证复现旧训练随机轨迹。
- 新入口显式设图像缩放 antialias=False，与旧 torchvision 0.14 张量 resize 默认行为对齐。跨环境比较应核对 torchvision 版本。
- 默认 workers=0，保存 Python/NumPy/Torch/CUDA/DataLoader RNG；恢复必须用同一 output 与相同参数。
- 每轮记录实际训练 lr、train loss、validation loss、pooled Dice/IoU、macro Dice、耗时；检测非有限输出/梯度并失败退出。
- `best.pth` 按固定阈值 0.5 的验证 pooled Dice 保存；`latest.pth` 含优化器、调度器、RNG、历史记录。检查点通过临时文件再替换，避免覆盖到一半。
- 不在训练结束自动评估测试集。输出目录必须新建，恢复时显式 `--resume`。

## 4. 第一笔 GPU 预算：最佳模型错误分析

```bash
python analyze_full.py \
  --ckpt results/vmunet_isic18_Friday_04_September_2026_11h_49m_31s/checkpoints/best-epoch199-loss0.2868.pth \
  --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json \
  --preprocessing legacy --gpu 0 --worst-k 20 \
  --output results/diagnosis_full_legacy
```

输出：

- `per_image.csv`：按 Dice 从低到高排列，含面积比例、Dice、IoU、boundary F1、HD95。
- `summary.json`：pooled 与 macro 指标分列；按 GT 面积比例分组（<5%、5–20%、≥20%）。这些是固定诊断分组，不是临床定义。
- 最差 20 张四联图：原图、GT、预测、错误图（红=误检，蓝=漏检）。
- `evaluation_pairs.json`：确切评估样本记录。

指标约定：所有指标在模型输入分辨率计算；HD95 单位是像素，不是毫米。空/空 Dice=1，单侧空 Dice=0；单侧空 HD95 未定义，输出 null/空值并单列数量，禁止只报剔除失败例后的平均 HD95。Boundary F1 容差默认 2 像素。Pooled Dice 与原项目全图像像素汇总口径一致，macro Dice 才是逐图平均，不能混用。

先检查该旧权重 pooled Dice 是否接近 0.8930886；若明显不同，停止比较，排查权重、配对、预处理和依赖。不要直接宣称新脚本已经复现该数字。

## 5. 当前实验：R3 保留预训练解码器的多尺度上下文恢复

### R2 已有结果与决策

2026-09-08 读取服务器结果：seed42 完成 300 轮，最佳 Dice=89.8743%，相对同种子 B0 +0.9890 个百分点；seed43 完成 300 轮，最佳 Dice=88.5868%，相对 B0 −1.3780 个百分点。两组均值下降约 0.1945 个百分点。seed44 当时约 192/300 轮，暂时最佳 89.7062%；它不是完整结果，不纳入完成实验的均值。

R2 seed43 的 boundary F1 从 B0 的 46.1883% 降到 38.0291%。两组均未出现非有限数值，后期训练损失降低而验证效果回落，有过拟合迹象，但不能据此断言某个分支是原因。代码和配置核对一致。停止扩展 R2 参数搜索，现有 `--decoder multiscale` 保留以读取历史检查点。

用户 GPU 预算紧张，下一轮直接评估一个整体结构候选，不逐个跑小模块消融。R3 的假设是：保留原版预训练编码器与解码器的已有能力，以联合上下文改善各层解码，并学习高分辨率残差修正。R2 放弃了解码器预训练，但现有实验尚不能证明这是退化原因；R3 也不保证涨点或新颖性。

### R3 结构与初始化

实现 `models/vmunet/context_adapter.py`，使用 `--decoder context`：

```text
原图 → 原 Mamba 编码器 → 四尺度特征分别投影 32 通道
                             ↓ 对齐到 1/4 分辨率并联合卷积融合为 64 通道
                             ├→ 三个尺度的上下文残差 → 原 skip 相加 → 原 Mamba 解码器
                             └→ 与解码器末端 1/4 特征拼接
                                  → 卷积 → PixelShuffle ×2 → PixelShuffle ×2 → 残差 logits
原解码器 → 原 FinalPatchExpand → 原分类头 logits ──────────────────────相加 → sigmoid
```

- 保留原 `layers_up`、`final_up`、`final_conv` 及原有预训练映射；不从 B0 已选最佳权重或 R2 权重热启动，仍使用同一个公开预训练文件。
- 四尺度来源与 R2 相同：patch embedding、两个中间下采样特征以及经过最后编码块的 bottleneck。上下文补充到原来的三处 skip，原相加路径保留。
- 高分辨率分支从编码/解码特征渐进恢复，不使用 R2 的原图旁路，也不使用竞争门控。
- 三个 skip 残差投影和最终残差分类层零初始化。新增模块安装在原预训练加载之后，保持原模块权重和 CPU RNG；初始预测与原版相同。首步只有残差输出层学习，输出层更新后梯度进入内部分支，这是预期行为。
- R3 总参数 27,967,610，其中新增分支 540,049；保留原网络并改变跨尺度信息流和恢复路径，参数增幅约 2%。
- 原模块与新分支一起训练，损失仍为 BCE+Dice，分辨率、batch、优化器及学习率计划与 B0 一致。R3 有额外计算，不能用 R2 的每轮耗时估计它。
- `decoder=context` 写入配置与检查点，分析工具自动恢复结构；不能把不同模型变体的 `latest.pth` 混用。R1 与 R2 继续可用，但不与 R3 组合。

### 有限 GPU 预算执行

先保留服务器未提交修改，再更新 main。新实验使用新的结果目录。本次代码更新不自动停止旧训练、不启动 GPU 任务。

```bash
# 本机/服务器的代码检查
python -m pytest -q tests

# 同 batch 一轮 CUDA 烟测，检查前后向、显存、保存；不作为效果结果
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_context_smoke \
  --decoder context --seed 43 --epochs 300 --stop-after 1 --gpu 0

# 第一阶段：固定 seed43，最多先投入 60 轮
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_context_s43 \
  --decoder context --seed 43 --epochs 300 --stop-after 60 --gpu 0

# 满足继续条件才执行第二阶段；保持同一目录、种子和完整学习率计划
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_context_s43 \
  --decoder context --seed 43 --epochs 300 --stop-after 120 --resume --gpu 0

# 第二阶段有持续增益才继续至 300 轮
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_context_s43 \
  --decoder context --seed 43 --epochs 300 --resume --gpu 0

python analyze_full.py --ckpt results/full_context_s43/best.pth \
  --data-path data/isic2018 --manifest splits/full_isic18_legacy.json \
  --output results/diagnosis_full_context_s43 --gpu 0
```

`--stop-after` 在该轮训练、验证、保存 latest/best 和 CSV 全部完成后正常退出；它不改变 `epochs=300` 或默认 `T_max=300`，也不进入检查点配置一致性比较，因此恢复时可以提高上限或取消它。不要通过把 `--epochs` 改成 60 来实现分阶段训练，那会改变学习率曲线。

固定先用 seed43，避免只重复 R2 恰好有利的 seed42；不能把选择种子当作统计证明。对照已有 `full_b0_s43/metrics.csv`，不用重跑 B0。预算检查点规则提前定为：

- 第 60 轮：若前 60 轮最佳 pooled Dice 和最近 20 轮平均 pooled Dice 都落后同阶段 B0 至少 0.5 个百分点，停止；否则仅继续到 120。
- 第 120 轮：前 120 轮最佳 pooled Dice 至少领先同阶段 B0 0.3 个百分点，且最近 20 轮平均 pooled Dice 领先至少 0.2 个百分点，才继续到 300；否则按本轮预算规则停止。
- 完整运行后仍有增益，才补 seed42/44 并报告全部配对结果。提前停止的运行单列为预算筛选，不能与 300 轮 B0 宣称公平终局比较。

这些是节约预算的启发式阈值，会错过晚期才改善的方法，不是显著性检验。检查由读取 CSV 后执行，上述命令不会自动判断指标或自动串联下一阶段。若同 batch 烟测显存不足，先评估额外对照成本，不直接降低 batch 后混入已有 B0 比较。

## 6. 正式论文协议与继续/停止标准

首轮单 seed 只筛选。正向后跑 seed=42/43/44，报告均值、标准差、每个 seed 的配对差值；方法有一致收益后再补第二数据集及相关强基线。不能保证 1–2 点提升，更不保证投稿结果。

正式协议可在原 train 内冻结验证集：

```bash
python prepare_full_split.py --data-path data/isic2018 \
  --val-fraction 0.2 --seed 42 --output splits/full_isic18_internal.json
```

此时 train 内所有剩余图像都使用标注，仍是全监督；但训练样本数减少，必须重跑 baseline。旧 val 已用于开发，不应称为严格未见测试；需要新的未触碰测试集/外部数据，且按患者或病灶分组，明确历史使用情况。独立数据可以整理为 `test/images`、`test/masks`，使用 `analyze_full.py --split test`，不传 manifest。

继续：相对新 B0 的改进在多 seed 可重复，诊断目标指标同时改善，第二数据集支持；再细化方法并做文献查重。停止或改方向：收益与随机波动相当、只在单 seed 出现、边界指标改善但整体显著恶化、训练设置变化解释了收益。先分析失败，不连续堆模块。
