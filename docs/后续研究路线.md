# VM-UNet 全监督研究路线

更新：2026-09-05。当前目标：使用全部训练标注，在公平协议下提高 VM-UNet 分割表现。先定位错误，再选择方法；不承诺提升幅度、创新性或录用概率。

旧扫描半监督路线已暂停，保留在 [历史文档](archive/扫描半监督路线_已暂停.md)。旧脚本和实验结果继续保留。半监督实验不再是当前主线，不自动启动、停止或排队任何远程任务。

## 2. 本次代码准备

| 文件 | 用途 |
|---|---|
| `audit_training.py` | CPU 解析历史日志，导出验证曲线及大幅下降记录；不猜测原因 |
| `prepare_full_split.py` | 按文件 ID 配对图像/掩码，冻结划分，检查路径和 train/val 完全相同的图像文件 |
| `analyze_full.py` | 加载旧/新权重，导出逐图指标、面积分组和最差案例图 |
| `train_full.py` | 独立全监督入口；逐轮验证、CSV、按 pooled Dice 选模型、原子检查点、断点恢复 |
| `fullsup/` | 数据、损失和指标实现 |

不改动原版 `train.py` 与 SSL 训练行为。新入口不是原实验的逐位复现：数据处理、随机数顺序、选模规则及默认学习率周期有明确变化，必须先跑新入口 baseline，再比较方法。

### 新入口的固定设置

- 模型配置与当前 ISIC 基线一致：depths=[2,2,2,2]，decoder=[2,2,2,1]，drop_path=0.2，单类输出。
- 默认 BCE + per-image soft Dice；全部训练样本使用人工标注；没有教师、伪标签、扫描扰动。
- AdamW，lr=0.001，weight_decay=0.01，batch_size=32，300 epochs，256×256。
- 默认 cosine T_max=epochs，避免旧 T_max=50 在 300 轮中反复下降/上升；这是一项协议变化，**尚不能据此解释旧异常**。可用 `--t-max 50` 做专门对照。
- `--preprocessing corrected`：每次增强重新采样旋转角，掩码最近邻缩放；图像仍用与旧实现代数等价的逐图 min-max 到 [0,255]，对常量图防除零。
- `--preprocessing legacy`：保留初始化单角度旋转、掩码双线性缩放；仅用于受控诊断，不保证复现旧训练随机轨迹。
- 新入口显式设图像缩放 antialias=False，与旧 torchvision 0.14 张量 resize 默认行为对齐。跨环境比较应核对 torchvision 版本。
- 默认 workers=0，保存 Python/NumPy/Torch/CUDA/DataLoader RNG；恢复必须用同一 output 与相同参数。
- 每轮记录实际训练 lr、train loss、validation loss、pooled Dice/IoU、macro Dice、耗时；检测非有限输出/梯度并失败退出。
- `best.pth` 按固定阈值 0.5 的验证 pooled Dice 保存；`latest.pth` 含优化器、调度器、RNG、历史记录。检查点通过临时文件再替换，避免覆盖到一半。
- 不在训练结束自动评估测试集。输出目录必须新建，恢复时显式 `--resume`。

python prepare_full_split.py --data-path data/isic2018 \

审查项目：检查学习率与掉点时间的对应关系、恢复训练记录、数据 ID 配对、异常图像/掩码、输入范围、检查点来源。图像字节哈希只发现完全相同文件；患者/病灶泄漏、重编码或近重复图像需要元数据与额外审查。

## 4. 第一笔 GPU 预算：最佳模型错误分析

```bash
python analyze_full.py \
  --ckpt results/vmunet_isic18_Friday_04_September_2026_11h_49m_31s/checkpoints/best-epoch199-loss0.2868.pth \
  --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json \
  --preprocessing legacy --gpu 0 --worst-k 20 \
  --output results/diagnosis_full_legacy
```

输出：

- `per_image.csv`：按 Dice 从低到高排列，含面积比例、Dice、IoU、boundary F1、HD95。
- `summary.json`：pooled 与 macro 指标分列；按 GT 面积比例分组（<5%、5–20%、≥20%）。这些是固定诊断分组，不是临床定义。
- 最差 20 张四联图：原图、GT、预测、错误图（红=误检，蓝=漏检）。
- `evaluation_pairs.json`：确切评估样本记录。

指标约定：所有指标在模型输入分辨率计算；HD95 单位是像素，不是毫米。空/空 Dice=1，单侧空 Dice=0；单侧空 HD95 未定义，输出 null/空值并单列数量，禁止只报剔除失败例后的平均 HD95。Boundary F1 容差默认 2 像素。Pooled Dice 与原项目全图像像素汇总口径一致，macro Dice 才是逐图平均，不能混用。

先检查该旧权重 pooled Dice 是否接近 0.8930886；若明显不同，停止比较，排查权重、配对、预处理和依赖。不要直接宣称新脚本已经复现该数字。

## 5. 第一轮方法实验：只选一个问题

根据失败图做决策：

| 观察 | 下一步 | 不应直接推断 |
|---|---|---|
| 主体正确但边界错误集中 | 边界加权损失探针；有效后再研究细化模块 | 加权损失本身就是创新 |
| 小病灶明显差 | 研究高分辨率细节与尺度融合，单独开实验 | 多尺度一定提高整体 Dice |
| 整块病灶漏检/伪影主导 | 检查数据增强、类别偏差、失败分布 | 单纯边界方法适用 |
| 训练后期异常 | 先修复训练，再跑新 baseline | 原架构不足导致异常 |

已准备 `--boundary-weight`：在 GT 的 5×5 形态学边缘带增加 BCE 权重，并按权重总和归一化；Dice 项保持不变。0 为 baseline，2 为一个预先指定的探针。**默认不开启，不新增网络模块，不作为论文贡献声明。** 增强边界监督是否有效由诊断和对照决定。

```bash
# 工程烟测：用单独目录；只确认能走完整训练/验证/保存，不能比较性能
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_smoke \
  --epochs 1 --batch-size 4 --gpu 0

# B0：新的受控全监督 baseline
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_b0_s42 \
  --seed 42 --gpu 0

# P1：只有错误分析支持边界问题时才跑，除边界权重外参数相同
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_boundary_s42 \
  --seed 42 --boundary-weight 2 --gpu 0

# 恢复 B0，必须保留原参数；不会自动寻找其他目录
python train_full.py --data-path data/isic2018 \
  --manifest splits/full_isic18_legacy.json --output results/full_b0_s42 \
  --seed 42 --gpu 0 --resume

# 新检查点自动读取训练时的分辨率和预处理
python analyze_full.py --ckpt results/full_b0_s42/best.pth \
  --data-path data/isic2018 --manifest splits/full_isic18_legacy.json \
  --output results/diagnosis_full_b0_s42 --gpu 0
```

比较顺序：旧 89.31 → 新 B0（训练协议变化）→ P1（仅方法变化）。不能将 P1 对旧 89.31 的全部差额归为方法贡献。固定同一 manifest、预训练权重、分辨率、训练步数、batch、种子、评估阈值和选模规则；显存不够时两组一起改 batch。不要一边改学习率一边加模块再做归因。

## 6. 正式论文协议与继续/停止标准

首轮单 seed 只筛选。正向后跑 seed=42/43/44，报告均值、标准差、每个 seed 的配对差值；方法有一致收益后再补第二数据集及相关强基线。不能保证 1–2 点提升，更不保证投稿结果。

正式协议可在原 train 内冻结验证集：

```bash
python prepare_full_split.py --data-path data/isic2018 \
  --val-fraction 0.2 --seed 42 --output splits/full_isic18_internal.json
```

此时 train 内所有剩余图像都使用标注，仍是全监督；但训练样本数减少，必须重跑 baseline。旧 val 已用于开发，不应称为严格未见测试；需要新的未触碰测试集/外部数据，且按患者或病灶分组，明确历史使用情况。独立数据可以整理为 `test/images`、`test/masks`，使用 `analyze_full.py --split test`，不传 manifest。

继续：相对新 B0 的改进在多 seed 可重复，诊断目标指标同时改善，第二数据集支持；再细化方法并做文献查重。停止或改方向：收益与随机波动相当、只在单 seed 出现、边界指标改善但整体显著恶化、训练设置变化解释了收益。先分析失败，不连续堆模块。

## 7. 租赁 GPU 使用顺序

1. 保存旧任务日志和 best/latest；经用户授权再停止，不由本代码自动处理。
2. CPU 测试与日志核查；GPU 空闲时执行一次旧模型诊断。
3. 分析结果、准备代码期间，按租赁平台规则暂停计费（停止 Python 不等于停止计费）。
4. 新入口短烟测，通过后跑 B0；根据诊断选择 P1，按顺序运行，避免抢显存。
5. 有收益才扩大种子/数据集，不预先排队大量实验。

当前完成的是代码准备与协议更新。真实数据的旧模型复评、完整 GPU 烟测、训练异常归因和方法增益验证，必须在后续运行中完成。
